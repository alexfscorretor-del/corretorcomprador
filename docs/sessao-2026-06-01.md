## 1. Contexto Geral do Projeto

SaaS para corretores de imóveis. O corretor cadastra clientes, define o perfil de busca de cada cliente e cadastra imóveis. O sistema calcula automaticamente a compatibilidade entre o perfil do cliente e cada imóvel. Existe uma página pública (`/catalogo/[id]`) gerada por cliente, onde o comprador visualiza os imóveis selecionados pelo corretor, avalia com estrelas e demonstra interesse via WhatsApp.

### Estrutura de tabelas Supabase relevantes

| Tabela | Descrição |
|---|---|
| `brokers` | Dados do corretor (user_id FK para auth.users) |
| `clients` | Perfil de busca do comprador, vinculado ao corretor |
| `properties` | Imóveis cadastrados, vinculados a um client_id |

Colunas relevantes em `properties`:
- `fotos` → `text[]` (array de URLs públicas do Supabase Storage, bucket `property-photos`)
- `avaliacao` → `int` (0–5, rating do comprador)
- `archived` → `boolean`

## 4. O Que NÃO Funcionou

### ❌ Lightbox com zoom nas fotos do modal de detalhe

**Sintoma reportado:** Ao abrir um card (modal de detalhe) e clicar nas fotos, o Lightbox não abre — a tela continua igual, sem nenhum zoom.

**Hipóteses investigadas:**

#### Hipótese A — z-index preso no stacking context (descartada parcialmente)
- O modal de detalhe tem `position: fixed` e `z-index: 500`
- Quando um elemento pai tem `position: fixed` + `z-index`, ele cria um **stacking context isolado**
- Qualquer filho, mesmo com `z-index: 99999`, fica visualmente preso dentro desse contexto
- **Solução implementada:** `ReactDOM.createPortal` → o Lightbox é renderizado diretamente no `document.body`, escapando do stacking context
- **Resultado:** O Portal foi implementado corretamente no código, mas o usuário reportou que ainda não funcionou

#### Hipótese B — `onClick` bloqueado por `e.stopPropagation()` no modal
- O modal inteiro tem `onClick={() => setShowDetail(false)}` no wrapper
- O conteúdo interno tem `onClick={(e) => e.stopPropagation()}`
- As thumbnails têm `onClick={() => setLightboxIdx(i)}` dentro da div com `stopPropagation`
- **Avaliação:** O `stopPropagation` está correto — não deve bloquear o `setLightboxIdx`
- **Não investigado a fundo:** Pode haver algum elemento overlay com `pointer-events` bloqueando o clique nas thumbs

#### Hipótese C — `lightboxIdx !== null` não disparando re-render
- O estado `lightboxIdx` é `number | null`
- `setLightboxIdx(0)` deveria disparar re-render e renderizar o `<Lightbox />`
- O Portal depende de `document.body` estar disponível (SSR vs Client)
- **Suspeita:** Em Next.js App Router com `'use client'`, o `document.body` só existe no cliente. Se houver qualquer erro de hidratação, o Portal pode falhar silenciosamente
- **Não testado:** Adicionar `typeof window !== 'undefined'` como guard antes do Portal

#### Hipótese D — arquivo `[clientId]` ainda presente no build
- Antes do commit `1825efa`, o Vercel falhava por rota duplicada
- Após a deleção, o build passou — mas o usuário não confirmou se o deploy com o Lightbox funcionou depois disso
- **Inconclusivo:** Pode ser que o build tenha passado mas o Lightbox ainda não funcione por outra razão

## 7. Problemas Técnicos Encontrados na Sessão (para referência futura)

### Bug: GitHub API + colchetes no path
- A API REST do GitHub (`contents/{path}`) **não consegue ler** arquivos em pastas com `[` `]` no nome via GET
- A criação (`PUT`) funciona — o arquivo vai pro Git tree mas não aparece na listagem via API
- O `push_files` (que usa a Tree API) **falha silenciosamente** — retorna commit SHA mas o blob não é gravado
- **Workaround confirmado:** Usar `create_or_update_file` (PUT direto) funciona para criar
- **Workaround para ler SHA:** Buscar via `list_commits` com `path` filter — mas também falha com colchetes
- **Solução definitiva:** Para deletar, usar `delete_file` sem SHA (a API aceita sem SHA em alguns casos)
- **Lição:** Sempre usar `[id]` em vez de `[clientId]`, `[propId]`, etc. — nomes curtos sem risco de encoding

### Ambiguous Routes no Next.js App Router
- Next.js trata `[qualquerNome]` como o mesmo padrão dinâmico
- Dois segmentos dinâmicos no mesmo nível (`[clientId]` e `[id]`) causam erro de build
- O erro é: `Ambiguous app routes detected: /catalogo/[*] matches multiple routes`
- **Solução:** Sempre garantir que existe apenas um segmento dinâmico por nível de rota
